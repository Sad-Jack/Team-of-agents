# Инструкции для Claude Code

## О проекте

Это локальная система управления разработкой с набором AI-агентов и управляемым workflow по задачам/багам.

## Ключевая архитектура

- `orchestrator.py` владеет workflow-состояниями и переходами.
- `llm_client.py` владеет выбором и вызовом LLM-провайдера.
- `agent_runner.py` владеет запуском агентов и JSON-парсингом ответов.
- `supervisor.py` владеет преобразованием natural language в безопасные действия.
- `storage.py` владеет выбором backend-а хранения и операциями коллекций.
- `managed_project.py` владеет разделением `system root` и `managed repo root`.

## Обязательные правила

- Не добавлять базу данных без явного запроса.
- Перед завершением работы все тесты должны проходить.
- Во всех командах использовать `python3`.
- Не коммитить секреты (`API keys`, токены, приватные данные).
- Предпочитать простой, понятный и проверяемый код.
- Не ломать существующие тесты.
- `FakeLLMClient` обязателен для тестов и детерминированных проверок.
- Перед добавлением новых фич запускайте `python3 run.py doctor` и тесты.
- Telegram-слой — только интерфейс:
  - route через `supervisor.py`
  - без дублирования бизнес-логики в хендлерах
  - owner-only режим обязателен
  - risky действия только с явным подтверждением
  - polling-only для MVP
  - токены/секреты не печатать
  - voice-ввод также только интерфейсный: transcript обязательно маршрутизируется в Supervisor
  - ffmpeg/STT вызовы только через `subprocess` с `shell=False`
  - STT по умолчанию выключен (`STT_PROVIDER=disabled`)
  - временные voice-файлы не коммитить

## MVP demo правила

- `demo-*` команды используются только для локальной валидации MVP.
- `demo-reset` считается destructive-командой и должен требовать `--yes`.
- `e2e-demo` не должен использовать платные API.
- `e2e-demo` не должен требовать Telegram-конфиг.
- Не удалять пользовательские данные, кроме явного `demo-reset --yes`.

## Storage правила

- JSON backend остается default.
- SQLite backend опционален и включается через env.
- Бизнес-логика не должна читать/писать JSON напрямую.
- Используйте `storage.load_collection/save_collection` или существующие wrapper API.
- Не добавлять внешние DB зависимости.
- Не реализовывать multi-project support на этом шаге.
- До интеграции новых фич запускайте `doctor` + тесты.

## Managed Project правила

- Система может быть встроена в другой репозиторий.
- `MANAGED_REPO_PATH` задаёт target project.
- По умолчанию `repo_inspector`, `patch_utils` и project-команды работают с managed repo.
- System-команды `python3 run.py ...` должны выполняться в system root.
- Нельзя путать system root и managed repo root в логике и тестах.

## Провайдеры

- Для реальной локальной работы предпочтителен `claude_code`.
- `openai` — опциональный/legacy провайдер.
- Для тестов и CI по умолчанию использовать `fake`.
- Тесты voice/STT должны быть полностью на моках (без реального Telegram/ffmpeg/whisper).

## Project Manager правила

- Project Manager слой (`project_manager.py`) — основной high-level пользовательский слой.
- Пользовательские PM-запросы должны идти через Supervisor/Project Manager, без bypass low-level слоёв.
- Low-level агенты остаются внутренними.
- `project_manager.py` может делать только безопасную многошаговую оркестрацию.
- Рискованные действия требуют explicit confirmation.
- `task.notes` используется как память обсуждений и должен проходить валидацию.
- Документация PM-слоя должна оставаться на русском.
