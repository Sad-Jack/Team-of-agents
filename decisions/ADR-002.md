# ADR-002: Telegram board — только отображение, приватный чат — для работы

- Status: accepted
- Date: 2026-05-03
- Tags: telegram, ux, architecture
- Related Tasks: TASK-5

## Контекст

Система использует Telegram как основной интерфейс управления проектом.
По мере развития появились два возможных подхода к использованию Telegram:

**Вариант A:** Единый канал — пользователь работает и в приватном чате, и в топиках forum-группы.
Топики поддерживают reply-to-task, обрабатывают свободный текст как команды.

**Вариант B:** Разделение ролей — forum-группа служит только доской статусов (display-only).
Все команды — только через приватный чат.

## Решение

Принят **Вариант B**. Telegram forum-группа используется исключительно как проектная доска:

- Топики содержат карточки сущностей (задачи, баги, релизы, решения).
- Топики не обрабатывают произвольный текст как команды.
- Reply-to-task workflow в топиках **не реализуется**.
- Все рабочие команды — только в приватном чате с ботом.
- Inline-кнопки на карточках (В фокус, В работу) направляют пользователя в приватный чат.

## Обоснование

1. **Простота модели.** Разделение display и interaction устраняет неоднозначность
   в том, какие сообщения являются командами.

2. **Надёжность маршрутизации.** Reply-to-message в forum-группах технически ненадёжен:
   Telegram может доставлять реплаи без `reply_to_message` при некоторых условиях.
   Отказ от этого механизма устраняет класс ошибок.

3. **Telegram не источник истины.** Данные живут в локальном JSON-хранилище.
   Board — это projection хранилища, а не primary storage.
   Карточки можно восстановить/перепостить в любой момент.

4. **Фокус-режим.** Inline-кнопка "В фокус" — правильная точка входа для работы с
   конкретной сущностью. Она устанавливает фокус и приглашает продолжить в приватном чате,
   где контекст явный, а не угаданный по thread-у.

5. **Расширяемость.** Board-топики можно использовать для agent log, release notes,
   decision records без риска смешивания с командным вводом.

## Последствия

### Положительные

- Чистая архитектура: display ≠ input.
- Нет ложных срабатываний на обычные сообщения в топиках.
- Карточки всегда восстановимы из хранилища.
- Agent Log в топике `🧾 Agent Log` даёт видимость без засорения приватного чата.

### Отрицательные / ограничения

- Пользователь не может ответить на карточку текстом — нужно перейти в приватный чат.
  Это дополнительный шаг, но он явный.
- Для работы с конкретной задачей в приватном чате нужно либо нажать кнопку на карточке,
  либо явно упомянуть ID (`TASK-6`) или установить фокус вручную.

### Исключённые варианты

- Reply-to-task в топиках — **не реализуется** (см. обоснование выше).
- Свободный текст в топиках как команды — **не маршрутизируется**.
- Telegram как хранилище (message ID как primary key) — **не используется**.
