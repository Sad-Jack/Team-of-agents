# Инструкция по багам

Используй этот шаблон для каждого нового бага в `work-items/bugs`.

## Формат файла
- Имя файла: `YYYY-MM-DD-short-title.md`
- Один файл = один баг

## Шаблон бага

```md
# Bug: <краткое название>

## Статус
[создан / выполнен]

## Где проявляется
- Сервис / экран / API:
- Окружение (prod / stage / local):
- Версия (если применимо):

## Фактическое поведение
Что происходит сейчас.

## Ожидаемое поведение
Что должно происходить.

## Шаги воспроизведения
1. ...
2. ...
3. ...

## Воспроизводимость
[всегда / иногда / 1 раз]

## Критичность
[блокер / высокий / средний / низкий]

## Контекст
Когда появилось, при каких условиях, связанные задачи.

## Предположение (опционально)
Возможная причина, если есть гипотеза.

## Артефакты
- Скриншоты:
- Логи:
- Запросы / ответы API:

## Зона проблемы (если известна)
[frontend / backend / API / интеграция / данные]

## Проверка после фикса
1. ...
2. ...

## Ответственный
<имя или роль>
```

## Когда баг считается закрытым
- Фактическое поведение приведено к ожидаемому.
- Баг не воспроизводится по шагам.
- Проверены соседние сценарии.
- Статус изменен на `выполнен`.
