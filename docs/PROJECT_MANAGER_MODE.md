# Project Manager Mode

## Концепция

`project_manager.py` — high-level слой, через который пользователь управляет проектом как единым PM-интерфейсом.

## Отличие от low-level CLI

- low-level команды работают с отдельными слоями (`orchestrator`, `release_manager`, `backlog`, ...)
- PM Mode агрегирует эти действия в понятные операции

## Примеры (Telegram/CLI)

- "Дай статус проекта"
- "Что делать дальше?"
- "Подготовь TASK-1 к разработке"
- "Добавь заметку к TASK-1: проверить edge case"
- "Что заблокировано?"
- "Дай статус релиза REL-001"

## Voice примеры

- "Подготовь TASK-2 к разработке"
- "Покажи, что заблокировано"

Голосовой ввод: Telegram voice -> ffmpeg -> STT -> Supervisor -> Project Manager action.

## Safety model

- Никаких прямых status-change из LLM.
- Рискованные действия остаются под явным подтверждением.
- Патчи не применяются автоматически PM-слоем.
- `project_manager.py` оркестрирует только безопасные шаги.

## Что умеет / не умеет

Умеет:
- сводный статус проекта
- подготовка задачи к разработке
- безопасное продвижение задачи
- заметки и сводка обсуждений
- сводка блокеров и релиза

Не умеет:
- обходить workflow-гейты
- выполнять risky shell-действия без подтверждения
- автоматически применять patch proposal

## Делегирование внутренним агентам

Пользователь работает с одним менеджером, а внутри используются существующие слои:
- Supervisor -> orchestrator / backlog / release_manager / repo_inspector / project_manager.
