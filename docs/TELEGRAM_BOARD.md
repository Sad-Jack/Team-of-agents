# Telegram Board — архитектура и правила

## Концепция

Telegram-бот существует в двух контекстах:

| Контекст | Назначение |
|---|---|
| **Приватный чат** | Рабочее пространство. Здесь пользователь отдаёт команды, получает ответы, работает с задачами. |
| **Forum-группа (Board)** | Доска статусов. Только отображение карточек сущностей. Не для команд и не для обсуждений. |

Эти два контекста **не смешиваются**.

---

## Forum-группа как доска

Forum-группа Telegram используется как проектная доска — аналог Kanban.
Каждый топик — это колонка для одной категории сущностей.

### Правило: Board только для отображения

- Топики не предназначены для ввода команд или переписки.
- Свободный текст в топиках **не маршрутизируется** как задача.
- Бот **не отвечает** на произвольные сообщения в топиках.
- **Reply-to-task workflow отсутствует.** Ответ на карточку в топике не создаёт команду.
- Работа с задачами ведётся **только в приватном чате**.

## Структура топиков

### Задачи

| Топик | Статусы задач |
|---|---|
| 💡 Tasks · Ideas | `idea` |
| ✅ Tasks · Ready | `ready` |
| 🚧 Tasks · Active | `in_progress`, `review` |
| ⛔ Tasks · Blocked | `blocked` |

### Баги

| Топик | Статусы багов |
|---|---|
| 🐞 Bugs · New | `new` |
| 🛠 Bugs · Active | `in_progress`, `verify` |

### Другие

| Топик | Содержимое |
|---|---|
| 🟡 Needs Input | Задачи и баги в статусе `need_info` |
| 🚀 Releases | Карточки релизов |
| 🧾 Agent Log | Лог событий агентов (run_next, advance, ошибки) |
| 📌 Decisions | Карточки ADR-решений |

## Статусы сущностей

### Задачи (`task`)

```
idea → ready → in_progress → review → done
                    ↓
                 blocked
                    ↓
                cancelled
```

| Статус | Описание |
|---|---|
| `idea` | Новая идея, не проработана |
| `ready` | Готова к разработке |
| `in_progress` | Активно выполняется |
| `review` | На ревью |
| `done` | Завершена |
| `blocked` | Заблокирована зависимостью |
| `cancelled` | Отменена |

### Баги (`bug`)

| Статус | Описание |
|---|---|
| `new` | Новый баг, не в работе |
| `in_progress` | Активно исправляется |
| `verify` | Исправление на проверке |
| `closed` | Закрыт |
| `need_info` | Нужна дополнительная информация |
| `cancelled` | Отменён |

### Релизы (`release`)

| Статус | Описание |
|---|---|
| `preparing` | Готовится |
| `publishing` | Публикуется |
| `published` | Опубликован |
| `failed` | Ошибка публикации |
| `rollback` | Откат |

## Карточки в топиках

Каждая сущность публикуется как карточка в соответствующем топике.
Карточка — это Telegram-сообщение с форматированным текстом и inline-кнопками.

### Пример карточки задачи

```
🧩 TASK-6: Проверить Telegram UX после merge

Статус: ready
Приоритет: medium

Провести проверку форматирования и навигации в Telegram
после последних изменений.

[⚡ В работу]  [📌 В фокус]
```

### Пример карточки бага

```
🐞 BUG-2: Краш при отправке голосового

Статус: new
Серьёзность: high

[⚡ В работу]  [📌 В фокус]
```

---

## Inline-кнопки

Карточки могут содержать inline-кнопки для быстрых действий.

| Кнопка | Действие |
|---|---|
| **⚡ В работу** | Переводит сущность в активный workflow (например, `idea → ready`). Устанавливает фокус. Отправляет сообщение пользователю в приватный чат. |
| **📌 В фокус** | Устанавливает сущность как активный фокус. Отправляет приглашение продолжить в приватном чате. |

### Правила кнопок

- Кнопки работают только для владельца бота (`TELEGRAM_OWNER_ID`).
- Нажатие кнопки **не выполняет** действие напрямую в топике.
- После нажатия бот отвечает в **приватном чате**, описывает что произошло, и ждёт дальнейших команд.
- Рискованные действия (например, запуск агентов) требуют подтверждения в приватном чате через `/yes`.

## Источник истины

**Источник истины — локальное хранилище** (`tasks/tasks.json`, `releases/releases.json`, `decisions/`).

Telegram-доска является только отображением. Это означает:

- Состояние задач берётся из JSON, не из Telegram.
- Карточки на доске можно **восстановить/перепостить** из локального хранилища в любой момент.
- Удаление сообщения из топика не удаляет задачу.
- Telegram не реплицирует данные и не является secondary storage.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOARD_ENABLED` | `false` | Включить Board-интеграцию |
| `TELEGRAM_BOARD_CHAT_ID` | — | ID форум-группы (отрицательное число для групп) |
| `TELEGRAM_TOPIC_TASK_IDEAS` | — | message_thread_id топика Ideas |
| `TELEGRAM_TOPIC_TASK_READY` | — | message_thread_id топика Ready |
| `TELEGRAM_TOPIC_TASK_ACTIVE` | — | message_thread_id топика Active |
| `TELEGRAM_TOPIC_TASK_BLOCKED` | — | message_thread_id топика Blocked |
| `TELEGRAM_TOPIC_BUGS_NEW` | — | message_thread_id топика Bugs · New |
| `TELEGRAM_TOPIC_BUGS_ACTIVE` | — | message_thread_id топика Bugs · Active |
| `TELEGRAM_TOPIC_NEEDS_INPUT` | — | message_thread_id топика Needs Input |
| `TELEGRAM_TOPIC_RELEASES` | — | message_thread_id топика Releases |
| `TELEGRAM_TOPIC_AGENT_LOG` | — | message_thread_id топика Agent Log |
| `TELEGRAM_TOPIC_DECISIONS` | — | message_thread_id топика Decisions |

Незаданные топики молча пропускаются — приложение не падает при отсутствии topic id.
Невалидные значения (не целое число) генерируют предупреждение в логах.

## Настройка forum-группы

1. Создай forum-группу в Telegram через **New Group → Enable Topics**.
2. Создай топики с именами из таблицы выше (иконки в названии обязательны для идентификации).
3. Добавь бота как администратора с правом **Post Messages**.
4. Укажи в `.env`:

```env
TELEGRAM_BOARD_ENABLED=true
TELEGRAM_BOARD_CHAT_ID=<id форум-группы>
TELEGRAM_TOPIC_TASK_IDEAS=<message_thread_id>
# ... остальные топики
```

Получить chat id форум-группы:
- Добавь бота в группу, напиши любое сообщение, открой:
  `https://api.telegram.org/bot<TOKEN>/getUpdates`
- Найди `"chat":{"id":...}` — это id (у групп отрицательный).

Получить message_thread_id топика:
- Открой нужный топик и перешли любое сообщение из него в `@userinfobot` или
  посмотри `message_thread_id` в ответе `getUpdates` при отправке сообщения в топик.

## Что реализовано сейчас (foundation layer)

Модуль `telegram_board.py` реализует фундаментный слой:

- `BoardTopic` — enum из 10 слотов топиков.
- `BoardConfig` — dataclass с topic id mapping, safe parsing из env.
- `load_board_config_from_env()` — читает все `TELEGRAM_BOARD_*` переменные.
  Невалидные topic id → предупреждение в логах, не падает.
- Роутинг-функции: `topic_for_task_status()`, `topic_for_bug_status()`,
  `topic_for_release_status()`, `topic_for_decision()`, `topic_for_agent_log()`.
- Форматтеры карточек: `format_task_board_card()`, `format_bug_board_card()`,
  `format_release_board_card()`, `format_decision_board_card()`, `format_agent_log_card()`.

**Telegram-публикация намеренно отсутствует в этом модуле.**
Модуль — чистый слой конфигурации и форматирования, без I/O.

## Ограничения текущей реализации (v1)

- Публикация карточек на доску не реализована — это следующий этап.
- Inline-кнопки "В работу" и "В фокус" не реализованы — следующий этап.
- Автоматическое обновление карточки при смене статуса не реализовано.
- Восстановление доски из хранилища не реализовано.

Документ фиксирует **архитектурное решение** и **целевую модель**,
а не текущее runtime-состояние.

Источник истины всегда — **локальное хранилище**, не Telegram.
